# 약 10km·두 경유지 주행 테스트 준비

2026-11-13. 실제 TMAP POI 검색과 도로 경로 응답으로 약 10km 코스를 구성하고 두 차량이 참가한 새 모임에서 계획을 제안·승인했다.

| 순서 | 장소 |
| --- | --- |
| 출발 | 대전시청 |
| 경유 1 | 유림공원 주차장 |
| 경유 2 | 한빛탑광장 엑스포과학공원 주차장 |
| 목적지 | 한밭수목원 주차장1 |

REST 경로는 **10,266m·예상 1,387초(23분 7초)**다. 교통 상황에 따라 SDK의 경로와 실제 재생 소요 시간은 달라질 수 있다. 카이스트 정문을 추가한 3경유지 대안은 10,847m로 확인했으며, 10km에 더 가까운 두 경유지 코스를 선택했다.

## 확인한 것과 막힌 것

- 1번의 계획 제안과 2번의 승인을 거쳐 두 경유지가 승인된 계획에 반영됐다.
- 1번에서만 새 실제 길안내를 명시적으로 1회 요청했다. SDK 진단의 `waypoint_count=2`로 전달까지 확인했다.
- SDK 응답은 **429 한도 초과**였다. 같은 날 앞선 2.48km 주행은 성공했으나 이번 요청은 거절됐다. 재시도하지 않았다. 정확한 한도 초기화 시각·잔여량은 이 응답으로 알 수 없다.
- 따라서 이번 **10km 실제 내비 주행·경유지 통과·완주·장시간 녹화는 아직 수행하지 않았다.** REST 경로 확인을 SDK 주행 성공으로 보고하지 않는다.

한도가 복구된 후 이 시나리오를 첫 길안내 요청에 사용한다. 두 경유지를 출발 전에 승인하면 중간의 별도 명시적 경로 변경 요청 없이 한 경로로 테스트할 수 있다. 주행 중 새 경유지를 추가·승인해 경로가 바뀌는 테스트는 별도의 SDK 재계산이 필요하므로 이번 사전 경유지 테스트와 구분한다.

성공한 SDK 경로 좌표·제한속도를 새로 추출해 1번·2번을 서로 다른 가변 속도로 움직인다. 거리 기준으로 끝까지 재생하고 약 20~30분 이상의 영상을 확보하는 것이 목표이며 실제 제한·정차에 따라 길어진다. 미확인 제한속도를 임의 값으로 채우지 않는다. 2번은 GPS·지도만 사용한다.

기존 `via_passed`는 경유점을 한 번이라도 지났는지만 나타내므로 두 지점 통과를 구분할 수 없었다. `NativeTmapActivity`에 SDK 경유지 통과 콜백 횟수인 `via_passed_count`를 추가하고 새 경로 요청 시 0으로 초기화하도록 보완했다. 다음 실제 주행에서 경유지 두 개의 통과 콜백과 최종 SDK 도착 이벤트를 함께 확인한다. 횟수는 장소 ID나 통과 순서를 직접 증명하는 값은 아니므로 경로 위치·화면도 함께 대조해야 한다.

보완한 APK 빌드와 앱 단위 테스트 7개가 통과했다. 429 응답 뒤 수정 APK를 재설치하거나 추가 SDK 요청을 보내지 않았으며, 통과 횟수의 실제 주행 검증은 아직 미실시다.
