# 지도 전용 가상 GPS·합류 주행 검증

2026-11-11, Pleos 에뮬레이터 `emulator-5554` / `emulator-5556`에서 실행했습니다. 두 기기 모두 `JourneyActivity` 지도 화면을 사용하며 정식 TMAP 네비 SDK는 실행하지 않습니다. TMAP REST 도로 경로와 지도 상품은 실제 호출합니다.

## 시나리오

목적지는 **한밭수목원 주차장1**(36.36548894, 127.39029492)로 고정합니다. 출발 조합마다 주행 중 경유지를 3번 제안하고 두 테스트 차량이 승인합니다. 지도 반영이 완료된 뒤 다음 제안을 진행합니다.

| 회차 | 1번 출발 | 2번 출발 | 경유지 추가·합류·공동 출발 | 최종 도착 | 소요 시간 |
|---|---|---|---|---|---|
| 1 | 대전시청 | 타임월드 | 3회 통과 | 두 차량 통과 | 262.1초 |
| 2 | 둔산동 남쪽 | 갈마동 동쪽 | 3회 통과 | 두 차량 통과 | 290.0초 |
| 3 | 갈마역 부근 | 월평동 | 3회 통과 | 두 차량 통과 | 272.7초 |
| 4 | 정부청사 서쪽 | 둔산동 동쪽 | 3회 통과 | 두 차량 통과 | 290.2초 |

가상 GPS의 목표 속도는 72km/h이고 1초 간격으로 도로 경로 좌표를 입력합니다. Android 에뮬레이터의 `geo fix`와 모임 위치 공유를 모두 갱신하며 위치 출처는 `demo`입니다. GPS가 도착했음을 확인하는 테스트이며 실제 차량 주행이나 정식 SDK 도착 인증은 아닙니다.

**4개 조합 모두 통과했습니다.** 경유지 추가와 합류·공동 출발은 총 12회입니다. 첫 경유지 대기 시간은 31.0·36.0·23.0·64.1초이고, 대기 중 위치 표본 총 15개에서 이동 거리는 모두 0m였습니다. 모든 차량이 고정 목적지에서 4.16m 떨어진 도로 끝 지점까지 도착했으며, 최종 Android GPS와 입력 좌표의 차이는 0.11m였습니다. 두 기기의 `NativeTmapCheck` SDK 실행 로그는 각각 0건입니다.

## 합류와 기기별 표시

- 각 경유지에서 먼저 도착한 차량은 **그 도로 지점에서 정지**하고 상대 차량을 기다립니다.
- 두 차량이 모두 도착한 뒤 최소 6초간 함께 정차하고 같은 시뮬레이션 시점에 출발합니다. 뒤늦게 도착한 차량을 좌표로 순간 이동시키지 않습니다.
- 각 기기에서 **내 차는 파란 A, 상대 차는 주황 B**입니다. 차량 목록·경로 색·지도 마커가 같은 기준을 사용합니다.
- 경유지는 보라색 1·2·3, 고정 목적지는 D입니다. 합류 지점에서도 차량 마커가 경유지 번호 위에 표시되도록 그립니다.
- 합류해 두 차량 마커가 같은 좌표에서 겹치면 자기 차량 A를 위에 표시합니다. 차량 목록에서는 두 차량을 계속 구분할 수 있습니다.

첫 회차에서는 먼저 도착한 차량이 약 31초 기다렸고, 대기 중 실제 서버 위치 표본 3개 모두 이동 거리가 0m였습니다. TMAP 도로에서 130m 떨어진 초기 가상 경유점은 실제 반환 도로 좌표로 옮겼습니다. 도로와 60m 넘게 떨어진 경유점으로는 합류 성공을 기록하지 않습니다.

```powershell
$python = Join-Path $env:TEMP 'codex-python-3.13.0/python.exe'
& $python -u -c "import sys,runpy;sys.path.insert(0,'server');runpy.run_path('server/test_map_emulators.py',run_name='__main__')"
```
