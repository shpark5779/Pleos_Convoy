# 5분 내비 주행 녹화와 제한속도 표지

> 후속: [2026-11-13 카메라 수정 후 주행·도착·영상 재검증](CAMERA_FIXED_DRIVING.md). 아래 영상은 2026-11-12 수정 전 기록이다.

2026-11-12. 기존 정식 SDK 길안내를 유지하면서 두 차량을 약 5분간 주행시켰다. 1번에만 내비를 켜고 2번은 GPS를 전송한다. 1번 내비 오른쪽 위에 빨간 원형 도로 제한속도 표지를 추가했다.

## 표지 구현

`SpeedLimitBadge.java`는 공식 SDK의 `observableRouteData`에서 경로 좌표와 `RoadInfo.maxSpeedKmh`를 읽는다. SDK 현재 위치를 경로에 투영해 현재 구간의 제한을 표시하고 현재 GPS 속도도 함께 보여 준다. 제한값이 없거나 경로에서 80m보다 멀면 미확인으로 표시한다. 이번 경로의 원자료는 앞선 보고서와 동일하게 50km/h 구간과 마지막 10km/h 구간이다.

이 표지는 앱에서 추가한 실제 Android View다. SDK 기본 과속카메라·안전운전 경고 표지를 강제로 켠 것은 아니다. 녹화 후 합성한 그래픽도 아니다. SDK의 공개 UI 옵션에서는 도로 제한을 항상 표시하는 스위치를 확인하지 못해 기존 SDK 도로정보를 재사용했다.

`NativeTmapActivity`에 자동 부착을 연결했고 디버그 APK 빌드와 JVM 테스트 7개가 통과했다. 현재 길안내를 종료하지 않기 위해 이 APK를 재설치하지 않았다. 대신 동일한 View 코드를 디버거로 실행 중인 Activity에 부착해 이번 주행에서 확인했다. 디버거 연결과 임시 중단점은 제거하고 주행했다. 이후 새 APK를 설치하면 Activity 진입 시 자동으로 붙는다.

249회 제어에서 두 차량의 적용 속도 **498개 표본 모두 제한 이하**였다. 내비 화면 접근성 값으로 0~180초에는 50 표지, 225~300초에는 10 표지를 확인했다. 8회 화면 표본 모두 동행 차량 1대가 등록되어 있었으며, 지도 안 보라색 차량 아이콘도 촬영했다. 카메라 시야 밖에 있는 차량은 화면에 계속 보이는 것은 아니다. 실행 중 앱 PID 18939를 유지했고 명시적 추가 SDK 길안내 요청과 APK 설치는 0회다. 종료 후 두 콘솔은 P·0km/h로 복원했다.

첫 녹화는 약 3분 지점의 로컬 콘솔 `RemoteDisconnected`로 중단됐다. 절대값을 설정하는 콘솔 HTTP 요청과 동일 ID의 세션 갱신에 한해 연결 끊김을 최대 3회 재시도하도록 공통 요청 함수를 보완했다. 같은 명령 재시도와 재시도 상한 테스트를 추가했고 서버 테스트 **41개 통과** 후 전체 5분을 다시 녹화했다. 위 영상과 표는 최종 재실행 결과다.

영상은 `docs/videos/2026-11-12/`에 Git LFS로 보관한다. 원본 녹화 경로 `build/`는 Git에서 제외한다. 두 차량은 동일한 SDK 도로 경로의 서로 다른 지점에서 출발하며 가속·감속·잠시 정차하는 시점과 속도가 다르다. 낮은 제한 구간에 들어가기 전에 감속한다. 실제 도로 교통·신호를 인식하는 자율주행이 아니라 에뮬레이터 GPS 재생이다.

## 재실행

실행 중인 내비 세션, 로컬 동행 서버, 준비된 테스트 GPS 공급자, SDK 경로 덤프와 표시 View가 필요하다. 추가 길안내 요청이나 앱 재시작은 하지 않는다.

```powershell
python server/record_long_guidance.py
python server/validate_long_guidance.py
```

주행 제어와 화면 캡처를 분리해 캡처 중에도 GPS가 계속 갱신된다. Android screenrecord의 무제한 녹화를 시작하고 주행 종료 후 해당 녹화 프로세스에만 종료 신호를 보내 MP4를 마무리한다. 종료 시 두 Virtual Console을 P·0km/h로 복원하고 GPS 속도도 0으로 만든다. 원래 GPS 공급자로 복원하는 명령은 [기존 보고서](ACTIVE_GUIDANCE_DRIVING.md)를 따른다.

기존 SDK 실패 콜백 문구가 화면 상단에 남는 문제는 유지되어 있다. 실제 주행 여부는 녹색 회전 안내 거리 변화, 지도 이동, 내비 차속, 동행 아이콘과 앱 PID 유지로 확인하며 진단 문구를 수동 변경하지 않았다.

## 후속 수정: 반복 확대·축소

기존 5분 영상의 카메라가 흔들리는 코드상 원인은 동행 지도 미리보기용 카메라 조작과 SDK 주행 카메라의 충돌이다.

- 기존 `native-map` 실행은 `external_gps_replay=true`, `convoy_overview=true`로 내비 Activity를 열었다.
- `companionTick`이 3초마다 동행 위치를 읽은 뒤 두 차량의 평균 위치로 `setMapCenter(..., false)`를 호출했다.
- 이어서 `moveCamera(CameraUpdateFactory.zoomTo(17f))`로 줌을 매번 강제했다. 길안내를 시작한 뒤에도 이 미리보기 모드가 남아 SDK 자동 추적과 번갈아 지도를 제어할 수 있었다.
- 동행 마커 갱신에서 카메라 이동 블록 전체를 제거하고 사용하지 않는 `convoy_overview` 인텐트와 속성도 제거했다. 카메라는 SDK에 맡기고 동행 위치 갱신은 마커만 변경한다. SDK 자체의 정상적인 교차로 확대·축소까지 끈 것은 아니다.

2026-11-12 수정 후 `assembleDebug`와 JVM 테스트 7개가 통과했고 1번 에뮬레이터에 수정 APK 설치가 성공했다. 추가 길안내 요청은 하지 않았다. 확인 당시 기존 앱 PID 18939는 종료된 상태였고 화면에는 기본 내비가 실행 중이어서, 과거 세션의 실제 플래그·카메라 호출을 디버거로 직접 확인하거나 수정 후 주행을 다시 녹화하지는 못했다. 위 원인 판단은 실행 스크립트·Activity 분기와 수정 전 영상에 근거한다. **이 문서의 기존 5분 영상은 수정 전이며, 수정 후 실제 주행의 부드러움은 아직 재검증하지 않았다.**

별도로 기존 재생 로그의 GPS 제어 간격은 중앙값 약 1.19초·최대 약 1.70초였다. 차량 위치나 동행 아이콘의 미세한 끊김은 입력·표시 주기도 살펴볼 부분이지만, 이 수치만으로 렌더링 프레임 저하를 단정하지 않는다.
