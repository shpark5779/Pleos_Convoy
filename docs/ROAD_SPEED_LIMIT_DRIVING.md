# SDK 도로 제한속도를 따르는 두 차량 주행

> 후속 구현: [5분 연속 주행 영상과 내비 안 원형 제한속도 표지](LONG_GUIDANCE_SPEED_SIGN.md).

2026-11-12. 기존 가변 속도를 도로 제한속도와 무관하게 재생하던 방식에서, **현재 내비 SDK가 제공하는 도로 구간별 제한속도 이하로 주행하도록 변경**했다. 두 차량의 서로 다른 가감속·정차는 유지하고 낮은 제한속도 구간에 도달하기 전에 감속한다. 기존 길안내와 앱 프로세스를 유지했으며 새 길안내 요청은 하지 않았다.

## 읽어 온 실제 데이터

공식 SDK의 `observableRouteData.roadInfos`에 있는 `RoadInfo.startVtxIndex`, `endVtxIndex`, `maxSpeedKmh`를 사용했다. 지도 화면의 숫자를 OCR로 추정하거나 고정 50을 넣은 것이 아니다. `maxSpeedKmh`의 단위는 km/h다. 기존 경로 좌표를 읽던 진단 도구 `server/DumpSdkRoute.java`가 도로 정보도 함께 저장하도록 확장했다.

현재 SDK 경로의 원자료는 6개 도로 구간이다. 연속된 동일 제한을 합치면 다음 두 구간이 된다.

| SDK 경로 누적 거리 | 도로 제한속도 |
| --- | --- |
| 0–약 2,062.2m | 50km/h |
| 약 2,062.2–2,273.3m | 10km/h |

[SDK 원자료: 좌표·구간 인덱스·제한속도](test-results/2026-11-12-active-guidance/speed-limits/sdk-road-source.json).

## 제어 방법

- 좌표 인덱스를 SDK 경로의 누적 거리로 변환해 각 차량의 현재 구간 제한을 조회한다.
- 차량별 목표 속도는 그 구간 제한의 서로 다른 비율로 변한다. 출발 가속과 서로 다른 시점의 짧은 정차를 포함한다.
- 전방 제한이 내려가면 제동 거리 기반 속도 상한을 미리 적용한다. 경계점을 지난 뒤에만 급하게 속도를 낮추는 방식이 아니다.
- 속도를 적분한 거리로 GPS를 이동시키고, 같은 속도를 Android 테스트 GPS와 Virtual Console 계기판에 전달한다.
- 모든 적용 틱에서 **현재 위치의 실제 제한 이하인지 검사**한다. 목적지에서는 0으로 정지한다.
- 제한이 0·누락·비정상 범위이면 `미확인`으로 취급한다. 제어 모델은 해당 구간 전에 멈추며, 현재 실행 도구는 경로에 미확인 구간이 하나라도 있으면 시작을 거부한다. 임의의 기본 제한속도를 가정하지 않는다.

구간 해석·제어는 `server/road_speed.py`에 있다. SDK 인덱스가 좌표 목록과 맞지 않으면 실행을 중단한다. 이는 에뮬레이터 주행 재생의 속도 제어이며 실제 차량 제어 기능은 아니다.

## 실제 주행 검증

50→10km/h 전환점을 통과하도록 1번은 경계 약 220m 전, 2번은 약 120m 전에서 시작했다. 같은 SDK 경로를 약 60초 재생하며 두 화면을 녹화했다.

| 차량 | 50km/h 구간의 관측 최고 속도 | 10km/h 구간의 관측 속도 |
| --- | --- | --- |
| 1번 | 약 47.41km/h | 약 8.52–10.00km/h |
| 2번 | 약 38.49km/h | 약 7.02–10.00km/h |

29개 제어 틱 × 두 차량의 **58개 적용 속도 표본 모두 제한 이하**였다. 두 차량이 낮은 제한 구간에 들어간 것도 검사했다. 내비 화면의 속도, 계기판, 위치 변화와 동행 차량 아이콘을 함께 확인했다. 테스트 종료 후 P·0km/h로 복귀했다. 전체 경로 완주 검사는 아니다.

첫 실행에서는 속도 상한 검사는 통과했지만 기존 ‘150m 이상 이동’ 조건이 저속 구간에 맞지 않아 실패했다. 제한속도 전환 구간의 실제 진입을 확인하는 조건으로 수정해 재실행했고 최종 결과를 저장했다.

## 재실행과 테스트

기존 성공한 내비 화면, 실행 중인 로컬 모임 서버, Android 테스트 GPS 브리지, `roads`가 포함된 최신 SDK 경로 덤프가 준비된 상태에서 실행한다. 테스트 도구가 입력하는 GPS 시작 위치는 경로의 속도 전환 구간으로 재배치된다.

```powershell
python server/record_active_guidance.py --obey-limits
python -m unittest discover -s server -p 'test_*.py'
```

제한속도 전환 전 감속, 경계점, 초과 방지, 미확인 구간 정지, 잘못된 인덱스와 입력 값, 차량별 다른 속도를 검사하는 테스트를 추가했다. **서버 테스트 40개 통과.** 앱 재설치·추가 SDK 길안내 요청 없이 검증했다. 원래 GPS 제공자로 돌아가는 방법은 [기존 실제 주행 보고서](ACTIVE_GUIDANCE_DRIVING.md)를 참고한다.
