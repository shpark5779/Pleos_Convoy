# 확대·축소 수정 후 실제 내비 주행

2026-11-13. 수정 APK를 두 에뮬레이터에 설치하고 새 모임을 구성했다. 1번만 정식 SDK 길안내를 요청했고 2번은 GPS·동행 지도만 사용했다. 1번 요청은 한 번에 성공해 `NAVIGATION_RUNNING`, 경로 2,477m·407초를 반환했다. 인증과 길안내를 구분하며 429 재시도는 하지 않았다.

## 이번에 검증하는 변경

동행 위치 갱신에서 지도 중심과 줌 17을 강제하던 코드를 제거한 버전이다. APK 재설치 후 일반 View인 제한속도 표지도 자동으로 붙었으며, 과거 세션에 붙였던 임시 디버거 View에 의존하지 않는다. 지도 카메라와 교차로 확대는 SDK가 제어한다. SDK의 정상적인 회전·교차로 확대를 모두 고정하는 설정은 아니다.

오늘 응답된 경로는 어제와 다르다. SDK 좌표 51개·도로정보 7개를 새로 읽어 이 경로를 재생했다. 실제 데이터는 약 2,401.47m까지 50km/h, 이후 목적지 약 2,477.72m까지 30km/h다. 어제의 50→10 값을 하드코딩하지 않고 오늘 받은 제한값을 적용했다.

`record_long_guidance.py`에서 세션 경로를 지정할 수 있도록 하고, 표지·구간 검사도 해당 SDK의 제한값 집합을 검증하도록 바꿨다. 영상 검증 도구도 날짜별 증거 경로와 실제 제한값을 받게 했다. 서버 테스트 41개 통과.

## 최종 검증

두 MP4 길이는 336.05초·337.25초다. 30·120·240·295·328초 프레임을 실제 디코딩했다. 330초 재생 시험에는 도착 후 동행 차량을 기다리며 정차하는 마지막 장면이 포함된다. 1번 GPS 이동 거리는 약 2,477.27m, 2번은 120m 앞에서 출발해 약 2,357.39m 이동했다.

321회 제어 × 두 차량의 속도 642개 표본 모두 현재 SDK 도로 제한 이하였다. 50 구간 최고 적용 속도는 A 47.50 / B 43.00km/h, 30 구간은 A 27.01 / B 24.77km/h였다. 1번의 SDK `ARRIVED`·`arrived_final=true`·목적지 이름 일치를 확인했다. 2번은 내비를 실행하지 않았으므로 SDK 도착 검증 대상이 아니다. 두 콘솔을 P·0km/h로 복원했다. 주행 중 앱 PID 유지와 동행 차량 등록도 확인했다.

카메라 비교는 수정 전·후 영상의 120~140초에서 0.5초 간격으로 지도 특징점을 추적했다. 유효 변환 중 8%보다 큰 배율 변화는 수정 전 3개, 수정 후 1개였다. 수정 전 124.0초의 축소(배율 약 0.905) 직후 124.5초에 확대(1.172)되는 왕복이 있었고, 수정 후 이 구간에서는 122.0초의 축소(0.837) 이후 즉시 반대 방향으로 튀는 패턴이 없었다. 연속 프레임도 확인했다. SDK의 정상적인 자동 배율 변화는 남아 있다. 두 날짜의 경로와 주야간 모드가 달라 이 비교를 전체 영상의 프레임 성능 측정이나 모든 흔들림 제거의 증거로 확대 해석하지 않는다.
